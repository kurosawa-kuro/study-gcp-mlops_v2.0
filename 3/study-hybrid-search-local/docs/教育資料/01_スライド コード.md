## 1. Meilisearch lexical adapter (① BM25 + filter)

`app/services/adapters/meilisearch_lexical_search.py` (核心 30 行)

```python
def search(self, *, query: str, filters: SearchFilters, top_k: int) -> list[LexicalResult]:
    headers = {"content-type": "application/json"}
    if self._master_key:
        headers["authorization"] = f"Bearer {self._master_key}"
    payload = {"q": query, "limit": top_k}
    filter_expr = _to_meili_filter(filters)
    if filter_expr:
        payload["filter"] = filter_expr
    url = f"{self._base_url}/indexes/{self._index_name}/search"
    resp = httpx.Client(timeout=self._timeout_seconds).post(url, json=payload, headers=headers)
    hits = resp.json().get("hits") or []
    return [LexicalResult(property_id=str(h["property_id"]), rank=i)
            for i, h in enumerate(hits, start=1)]
```

- `_to_meili_filter` が `rent <= 150000 AND layout = "2LDK" AND pet_ok = true` の式を組む
- 戻り値は `(property_id, rank)` のリスト (`rank` は 1-based)
- 失敗時は **空リスト** にして `/search` を 503 にしない (RRF 融合で semantic 単独に縮退)

## 2. multilingual-e5 encoder (③' エンベディング)

`app/services/adapters/local_e5_encoder.py` (実質 25 行)

```python
def embed(self, text: str, kind: Literal["query", "passage"]) -> list[float]:
    prefix = "query: " if kind == "query" else "passage: "
    prepared = prefix + (text or "")
    vec = self._model.encode(
        [prepared],
        normalize_embeddings=True,   # L2 正規化済 → cosine = dot product
        show_progress_bar=False,
    )[0]
    return [float(x) for x in vec]
```

### ME5 のお作法 (重要)

- **クエリ側**は `query:` prefix、**文書側**は `passage:` prefix
- `normalize_embeddings=True` で **L2 正規化済** を返す
  → cosine 類似度を内積で計算できる
- 出力は **384 次元** (small) / 768 次元 (base) — DB 側 `vector(N)` と必ず一致させる
- `max_seq_length=512` で日本語の長文を切り詰める

## 3. pgvector semantic adapter (③' ANN)

`app/services/adapters/pgvector_semantic_search.py` 核心 SQL

```python
sql = f"""
    SELECT p.property_id, e.embedding <=> %s::vector AS distance
    FROM {self._table} AS e
    JOIN properties AS p ON e.property_id = p.property_id
    WHERE {where_sql}
    ORDER BY distance ASC
    LIMIT %s
"""
vec_literal = json.dumps([float(x) for x in query_vector])  # → "[0.1, 0.2, ...]"
cur.execute(sql, [vec_literal, *params, int(top_k)])
for rank, (pid, distance) in enumerate(cur.fetchall(), start=1):
    sim = max(0.0, 1.0 - float(distance))   # similarity = 1 - cosine_distance
```

### ポイント

- **`<=>`** は pgvector の **cosine distance** 演算子 (0=同一、2=逆方向)
- pgvector は **配列リテラル** (`[0.1, 0.2, ...]`) を受け付ける → `json.dumps` で生成
- WHERE 句に lexical と同じフィルタを当てて **両系統で同じ候補母集団** にする
- 失敗時は空リスト fallback

## 4. RRF 融合 (④ Reciprocal Rank Fusion)

`app/services/ranking.py::rrf_fuse` (実質 15 行)

```python
RRF_K: int = 60

def rrf_fuse(*, lexical_results, semantic_results, top_n, k=RRF_K) -> list[str]:
    scores: dict[str, float] = {}
    for property_id, rank in lexical_results:
        scores[property_id] = scores.get(property_id, 0.0) + 1.0 / (k + rank)
    for property_id, rank in semantic_results:
        scores[property_id] = scores.get(property_id, 0.0) + 1.0 / (k + rank)
    sorted_ids = sorted(scores.items(), key=lambda kv: kv[1], reverse=True)
    return [pid for pid, _ in sorted_ids[:top_n]]
```

### なぜ RRF か

- BM25 score と cosine similarity は **スケールが違う** ので加算融合は危険
- **順位だけを使う** ことで両系統を公平に統合
- 数式: `Σ (1 / (k + rank))`、`k=60` は元論文 (Cormack 2009) の慣例
- 上位ほど大きく、下位は急速に減衰 (1/61, 1/62, ..., 1/160)

## 5. Local CandidateRetriever (3 段の組み立て)

`app/services/adapters/local_candidate_retriever.py` (核心 40 行)

```python
def retrieve(self, *, query_text, query_vector, filters, top_k) -> list[Candidate]:
    # 1. lexical / semantic を独立に取得
    lex = self._lexical.search(query=query_text, filters=filters, top_k=self._pool_size)
    sem = self._semantic.search(query_vector=query_vector, filters=filters, top_k=self._pool_size)

    # 2. RRF 融合 → top_k に絞る
    fused_ids = rrf_fuse(
        lexical_results=[(r.property_id, r.rank) for r in lex],
        semantic_results=[(r.property_id, r.rank) for r in sem],
        top_n=top_k, k=self._rrf_k,
    )

    # 3. lexical / semantic / similarity を index 化
    lex_by_id = {r.property_id: r.rank for r in lex}
    sem_by_id = {r.property_id: r.rank for r in sem}
    sim_by_id = {r.property_id: r.similarity for r in sem}

    # 4. PostgreSQL から property の表示用 + ranker 補助特徴量を JOIN
    property_features = self._fetch_property_features(fused_ids)

    # 5. Candidate 組み立て (lexical_rank / semantic_rank / me5_score を埋める)
    return [Candidate(property_id=pid,
                      lexical_rank=lex_by_id.get(pid, 0),
                      semantic_rank=sem_by_id.get(pid, 0),
                      me5_score=float(sim_by_id.get(pid, 0.0)),
                      property_features=property_features.get(pid, {}))
            for pid in fused_ids]
```

> Phase 4 では `BigQueryCandidateRetriever` に差し替える (BQ JOIN 1 本で完結)。**Port は不変**。

class LocalLightGBMReranker(RerankerClient):
    def __init__(self, *, model_path: str) -> None:
        import lightgbm as lgb
        self._booster = lgb.Booster(model_file=model_path)
        self._model_path = model_path

    def predict(self, instances: list[list[float]]) -> list[float]:
        if not instances:
            return []
        matrix = np.asarray(instances, dtype=np.float64)
        preds = self._booster.predict(matrix)
        return [float(x) for x in np.asarray(preds).ravel()]

candidates = retriever.retrieve(query_text=lexical_query, query_vector=query_vector,
                                filters=filters, top_k=top_k)
if reranker is not None:
    matrix = [[float(row[col]) for col in FEATURE_COLS_RANKER]

## 10. SearchService — 全体 orchestration (③〜⑥)

`app/services/search_service.py::SearchService.search` (核心 30 行)

```python
def search(self, *, request_id: str, input: SearchInput) -> SearchOutput:
    # ① SYN-2 cache lookup — HIT で残り全 skip
    if self._search_cache is not None:
        cached = self._search_cache.get(input)
        if cached is not None:
            return SearchOutput(request_id=request_id,    # live id をスタンプ
                                items=cached.items,
                                model_path=cached.model_path,
                                ranked=cached.ranked)

    # ② encoder は元クエリ (embedding を希釈しない)
    query_vector = self._encoder.embed(input.query, "query")

    # ③ lexical のクエリだけ SYN-1 で展開
    lexical_query = (self._synonym_expander.expand(input.query)
                     if self._synonym_expander is not None else input.query)

    # ④〜⑥ 通常 pipeline
    ranked = run_search(retriever=retriever, publisher=publisher,
                        request_id=request_id, query_text=lexical_query,
                        query_vector=query_vector, filters=input.filters,
                        top_k=input.top_k, reranker=self._reranker, ...)

    output = SearchOutput(request_id=request_id, items=items, model_path=model_path, ranked=ranked)

    # ⑦ MISS だったので write-through
    if self._search_cache is not None:
        self._search_cache.set(input, output)
    return output
```

### 設計上の重要点

- **encoder と retriever でクエリが違う** (semantic は元クエリ、lexical は展開後)
- HIT 時に **publisher を呼ばない** = 元 MISS で済 → ranking_log の重複を防ぐ
- HIT 時に **新 request_id をスタンプ** = `/feedback` tracking が壊れない

## 11. Redis SYN-1 同義語辞書 (ranking 精度)

`app/services/adapters/redis_synonym_expander.py` 核心 25 行

```python
class RedisSynonymExpander(SynonymExpanderPort):
    DEFAULT_KEY_PREFIX = "syn:"

    def expand(self, query: str) -> str:
        tokens = query.split()
        if not tokens: return query
        try:
            return self._expand_tokens(tokens)
        except Exception:
            logger.exception("RedisSynonymExpander failed; using original query")
            return query        # 失敗時は元クエリにフォールバック

    def _expand_tokens(self, tokens: list[str]) -> str:
        seen, out = set(), []
        for tok in tokens:
            if tok and tok not in seen:
                out.append(tok); seen.add(tok)
            members = self._client.smembers(f"{self._prefix}{tok}")  # → SET<bytes>
            decoded = sorted(m for m in (_decode(raw) for raw in members) if m)
            for syn in decoded[: self._max_synonyms_per_token]:
                if syn not in seen: out.append(syn); seen.add(syn)
        return " ".join(out)
```

```text
"駅近 1K"
  → SMEMBERS syn:駅近 = {駅徒歩, 駅から徒歩, アクセス良好}
  → SMEMBERS syn:1K   = {ワンルーム, 1R}
  → "駅近 駅徒歩 駅から徒歩 アクセス良好 1K ワンルーム 1R"
```

- **辞書は YAML** (`definitions/synonyms/real_estate_ja.yaml`) → `make seed-synonyms` で Redis に投入
- **失敗時 graceful degrade** が効くので Redis 落ちても `/search` は動く

## 12. Redis SYN-2 レスポンスキャッシュ (UX/latency)

`app/services/adapters/redis_search_cache.py` 核心 30 行

```python
class RedisSearchCache(SearchCachePort):
    KEY_VERSION = "v1"

    def get(self, request: SearchInput) -> SearchOutput | None:
        try:
            raw = self._client.get(self._key(request))
        except Exception:
            return None     # 障害時は MISS と同じ扱い
        if raw is None: return None
        return self._deserialize(raw)

    def set(self, request: SearchInput, output: SearchOutput) -> None:
        try:
            payload = json.dumps(self._serialize(output), ensure_ascii=False)
            self._client.setex(self._key(request), self._ttl, payload)
        except Exception:
            logger.exception("RedisSearchCache.set failed; next request will MISS")

    def _key(self, request: SearchInput) -> str:
        spec = {"v": self.KEY_VERSION,
                "q": request.query,
                "f": sorted(dict(request.filters).items()),    # 辞書順序非依存
                "k": request.top_k,
                "e": bool(request.explain)}
        raw = json.dumps(spec, ensure_ascii=False, sort_keys=True)
        digest = hashlib.sha256(raw.encode("utf-8")).hexdigest()[:32]
        return f"{self._prefix}{self.KEY_VERSION}:{digest}"
```

### キャッシュに含めない / 含める

- **含めない**: `request_id` (caller が live id をスタンプ) / `ranked.property_features` (publisher が動かないので不要)
- **含める**: items の `property_id` / 各 rank / score / 表示用メタ + `model_path`
- key は **`(query, filters, top_k, explain)`** の sha256 → フィルタ辞書の順序非依存

## 15. 評価メトリクス NDCG@K

`ml/evaluation/metrics/ranking.py`

```python
def _dcg(labels: np.ndarray) -> float:
    """Discounted cumulative gain with log2(rank+2) discount."""
    gains = (2.0 ** labels - 1.0).astype(float)
    discounts = np.log2(np.arange(labels.size) + 2.0)
    return float(np.sum(gains / discounts))

def ndcg_at_k(labels: np.ndarray, scores: np.ndarray, *, k: int) -> float:
    order = np.argsort(-scores, kind="stable")          # 予測 score 降順
    ranked_labels = labels[order][:k]
    ideal_labels  = np.sort(labels)[::-1][:k]           # 真のラベル降順 = ideal
    ideal = _dcg(ideal_labels)
    return _dcg(ranked_labels) / ideal if ideal > 0 else 0.0
```

### 数式

```text
DCG  = Σᵢ (2^lᵢ - 1) / log₂(i + 1)
IDCG = ラベル降順での DCG (= 理想)
NDCG@k = DCG / IDCG    ∈ [0, 1]
```

- 上位ほど重み大 (log2 discount)
- ラベル `l_i ∈ {0,1,2,3}` の 4 段階に対して `2^l - 1` で gain を増幅 → inquiry (3) は click (1) の 4 倍効く
- IDCG (理想順序の DCG) で割って [0,1] に正規化

## 16. MAP / Recall@K

```python
def mean_average_precision(labels, scores) -> float:
    order = np.argsort(-scores, kind="stable")
    relevant = (labels[order] > 0).astype(int)        # binary relevance
    if relevant.sum() == 0: return 0.0
    cum = np.cumsum(relevant)
    precisions = cum / (np.arange(relevant.size) + 1)  # P@1, P@2, ...
    return float(np.sum(precisions * relevant) / relevant.sum())

def recall_at_k(labels, scores, *, k) -> float:
    total_relevant = int((labels > 0).sum())
    if total_relevant == 0: return 0.0
    order = np.argsort(-scores, kind="stable")
    return float((labels[order][:k] > 0).sum() / total_relevant)

def evaluate(labels, scores, groups, *, k_ndcg=10, k_recall=20) -> dict[str, float]:
    # クエリ単位 (group) で計算 → 全クエリで平均
    ndcgs, maps, recalls = [], [], []
    for start, end in _iter_groups(groups):
        ndcgs.append(ndcg_at_k(labels[start:end], scores[start:end], k=k_ndcg))
        maps.append(mean_average_precision(labels[start:end], scores[start:end]))
        recalls.append(recall_at_k(labels[start:end], scores[start:end], k=k_recall))
    return {"ndcg_at_10": np.mean(ndcgs), "map": np.mean(maps), "recall_at_20": np.mean(recalls)}
```

### per-query group 集計が肝

- **クエリごとに評価 → 平均** (クエリ間の relevance スケール差を吸収)
- `_iter_groups` で `groups = [8, 8, 8, ...]` を `[(0,8), (8,16), (16,24), ...]` に展開
- `kind="stable"` で同点解消順を保つ (再現性)

## 18. まとめ — Phase 3 の中核技術

1. **lexical / semantic / rerank の 3 段** を別々の Port で分離
   → 学習段階で技術を 1 つずつ置き換えながら理解できる
2. `multilingual-e5` の **prefix + L2 正規化** が cosine の前提
3. `pgvector <=>` で **生の SQL** で書ける ANN
4. **RRF は数式 1 行** で 2 系統を統合 (順位だけ使う)
5. **LambdaRank が NDCG を直接最大化** (回帰ではなくランキング)
6. Redis を **2 役割** で活用:
   - SYN-1 同義語辞書 → ranking 精度 (BM25 recall 改善)
   - SYN-2 レスポンスキャッシュ → UX/latency
7. NDCG / MAP / Recall@K は **クエリ単位集計 → 平均**

> Phase 4 では **adapter だけ Cloud SDK に差し替え**。Port / domain / RRF / 特徴量定義は不変。
