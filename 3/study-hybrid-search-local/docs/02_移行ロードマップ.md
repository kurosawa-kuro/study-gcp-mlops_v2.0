## 0. 改訂方針注記 (2026-05-03)

親 [`README.md` §4 コード化方針](../../../README.md) で、教育コード化対象 Phase が **Phase 1 / 2 / 3 / 4 / 7** に限定された。Phase 5 / 6 は独立コード保守をやめ、**Phase 7 完成版コードを参照する論理 Phase** に変更。Phase 4 は Phase 7 からの引き算ではなく **Phase 3 からの足し算 (local → cloud)** として独立コード化する。

これに伴い Phase 3 の位置づけは下記に整理される:

- Phase 3 は **コード化対象**。`pre-phase3to6-impl-removal` tag に残された旧実装を復元するのではなく、Phase 7 (canonical) を起点にして **GCP / Kubernetes 系を引き算した Local 完成形** として再構築する
- Phase 3 は **Phase 4 の起点 (足し算チェーン Phase 1→2→3→4 の中継地)** であり、不変 Port を保ったまま adapter を Cloud Run / BigQuery / GCS に差し替えると Phase 4 になる構造を維持する
- 本 phase の検証は **ローカルで一巡** (`make build && make seed && make train && make serve` → `curl /search` で 3 系統 (lexical / semantic / rerank) all non-zero) を達成すれば「完了」とする

参照: 親 [`README.md` §4 コード化方針](../../../README.md) / [`README.md` §4.4 Phase 2 → 3 の接続](../../../README.md) / [`README.md` §4.5 Phase 3 → 4 の接続](../../../README.md)。

## 2. 不変ルール (Phase 3 で絶対に変えない)

### 2.1 題材 / 中核 5 要素

| 段 | Phase 3 (Local) 実装 | Phase 7 (canonical) 実装 |
|---|---|---|
| (1a) Lexical | **Meilisearch (Docker)** BM25 + filter | Meilisearch on Cloud Run (Identity Token 認証付) |
| (1b) Semantic encoder | **multilingual-e5 (local in-process)** sentence-transformers (CPU) | KServe `property-encoder` InferenceService (HuggingFace runtime) |
| (1b) Semantic vector store | **pgvector** (`<=>` 演算子 ANN) | Vertex Vector Search (BQ は embedding 履歴正本) |
| (2) 融合 | **RRF** (Reciprocal Rank Fusion、`RRF_K=60`) | (Phase 3-7 共通、`app/services/ranking.py::rrf_fuse` 不変) |
| (3) Rerank | **LightGBM LambdaRank (in-process)**、`ml/registry/artifacts/{run_id}/model.lgb` 直読み | KServe `property-reranker` InferenceService |

中核 5 要素 (Meilisearch BM25 / multilingual-e5 / ベクトルストア / RRF / LightGBM LambdaRank) の挙動・データフロー・デフォルト `/search` 応答は **Phase 3-7 共通で不変**。canonical 仕様は [Phase 7 docs/01 §2](../../../7/study-hybrid-search-gke/docs/architecture/01_仕様と設計.md)。

### 2.2 設計思想 (Phase 2 から継承)

- Port/Adapter 構造 (`app/services/protocols/` Port + `app/services/adapters/` Adapter + `app/services/noop_adapters/` テスト用 fallback)
- 依存方向 `core → ports ← adapters` (services は Port のみ import、adapter import 禁止)
- Composition root = `app/composition_root.py` のみで DI 配線 (handler は `Depends(get_container)`)
- `scripts/ci/layers.py` で Port-Adapter 境界を AST 検査 (`make check-layers`)

### 2.3 実行基盤

- uv workspace (Python 3.12)
- Docker Compose 1 stack (postgres + pgvector / meilisearch / redis / search-api)
- `Cloud / Vertex / GKE / KServe / KFP / Composer は持ち込まない` (Phase 4 / 7 の責務)

### 2.4 API

- `/search` — 自由文クエリ + 構造化フィルタ → 物件ランキング上位 N 件 (lexical + semantic + RRF + rerank の 3 段)
- `/feedback` — 行動ログ受付 (PostgreSQL `feedback_events` に書き込み)
- `/health` — liveness

### 2.5 教材対象外

Agent Builder / Vizier / Model Garden / Gemini RAG / W&B / Looker Studio / Doppler は全 Phase 禁止 (親 [`README.md` §1](../../../README.md) 教材対象外)。

## 5. 検証方法

Phase 3 の **「完了」判定基準**。本セクションを満たさない限り「Phase 3 再構築完了」と書かない。

### 5.1 ローカル E2E

```bash
make build           # docker compose build
make seed            # synthetic properties → PostgreSQL + Meilisearch + pgvector
make train           # LightGBM LambdaRank → ml/registry/artifacts/{run_id}/model.lgb
make serve           # uvicorn 起動 (background)
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"駅近 2LDK","filters":{"city":"Tokyo","price_lte":150000},"top_k":10}'
```

**合格条件**: response の各 item に `lexical_rank` / `semantic_rank` / `final_rank` が **all non-zero** で入る (3 系統が動いている証拠)。少なくとも 1 件は rerank の `score` が `0.0` 固定 fallback でない (LightGBM が動いている証拠)。

### 5.2 ユニット / Lint / 型

```bash
make check           # ruff + ruff format --check + mypy strict + pytest
make check-layers    # AST 境界検査 (Port が adapter / google.cloud / lightgbm を import していないこと)
```

**合格条件**: exit 0、警告ゼロ。`google.cloud` import が混入していたら即 fail (`scripts/ci/layers.py` で検出)。

### 5.3 Integration

```bash
make verify-pipeline   # tests/integration/test_pipeline_e2e.py
```

**合格条件**: seed → train → serve の 1 cycle で `/search` が rerank 結果を返し、`ranking_log` テーブルに row が 1 以上挿入される。`/feedback` で 200。

### 5.4 NDCG@10 ベースライン

`ml/registry/artifacts/{run_id}/metrics.json` に NDCG@10 / MAP / Recall@20 がすべて `> 0` で記録されている。合成データなので絶対値は問わないが、**rerank 経路がモデル予測を反映している** ことを示す指標として `ndcg@10 > ndcg@10_baseline_random` (ランダムランキングの NDCG より高い) を満たすこと。

## 6. リスクと回避策

| リスク | 対象 | 影響 | 回避策 |
|---|---|---|---|
| sentence-transformers の初回 download (~500MB) でビルドが遅延 | `LocalE5Encoder` | `make seed` / `make serve` 初回起動が数分かかる | Dockerfile で `RUN python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('intfloat/multilingual-e5-base')"` を build 時に実行し model を image に焼き込む |
| sentence-transformers の CPU メモリ消費 (~2GB) | search-api コンテナ | 8GB 以下のローカル環境で OOM | `e5_model_name` を default `intfloat/multilingual-e5-small` (~470MB / 384 dim) に変更可能にする (setting.yaml で切替)、ただし pgvector の `vector(N)` 列の N も合わせて変更が必要なため migration を分岐 |
| pgvector の HNSW index が seed 量で過剰 | `embeddings` テーブル | seed 1000 件では index なしの seq scan のほうが速い場合がある | Wave 1 では `IVFFLAT` / `HNSW` を貼らず seq scan、Wave 4 で `CREATE INDEX ON embeddings USING hnsw (embedding vector_cosine_ops)` を貼って性能差を計測 |
| Phase 4 への足し算性破壊 | Port 定義 | Phase 4 で `MeilisearchLexical` を Cloud Run 認証付に差し替えるとき Port シグネチャが変わると全 Phase に波及 | Port (`LexicalSearchPort` / `EncoderClient` / `SemanticSearchPort` / `RerankerClient` / `FeatureFetcher` / `RankingLogPublisher` / `FeedbackRecorder`) を Phase 7 と完全同型で持ち込む。Phase 4 での差し替えは adapter のみ |
| `LightGBM` model.lgb format の互換 | `LocalLightGBMReranker` | Phase 4 / 7 で別バージョンの lightgbm に切り替えると Booster が読めない | `pyproject.toml` で `lightgbm>=4.5,<5` を Phase 3-7 共通で固定、CLAUDE.md にこの制約を記載 |
| Meilisearch master key の漏洩 | `env/secret/credential.yaml` | git commit に master key が混入 | `.gitignore` に `env/secret/credential.yaml` を追加、`env/secret/credential.yaml.example` のみ commit、Wave 1 で確認 |
| Docker Compose の startup order race | `seed` / `trainer` service | postgres が ready 前に seed が走る | Phase 2 同パターンで `depends_on.condition: service_healthy`、`pg_isready` healthcheck を必ず付ける |

`app/services/adapters/` 配下の 7 adapter (Phase 3 Local 版)。すべて Port のシグネチャを満たし、Phase 4 で同 Port の Cloud SDK 版 adapter を別ファイルとして追加する形で足し算可能。

### 7.3 ML パイプライン

- `pipeline/data_job/main.py` — synthetic seed (Phase 4 で BigQuery 連携の loader に差し替え可能)
- `pipeline/training_job/main.py` — LightGBM LambdaRank trainer (Phase 4 で Cloud Run Jobs 経由で起動、Phase 7 で Vertex AI Pipelines に昇格)
- `pipeline/evaluation_job/main.py` — NDCG@10 / MAP / Recall@20 計算 (Phase 4 で BigQuery 経由に差し替え可能)

### 7.4 検証ゲート

- `make check` (ruff + mypy strict + pytest)
- `make check-layers` (AST 境界検査)
- `make verify-pipeline` (integration E2E)
- NDCG@10 ベースライン (`metrics.json`)

すべて Phase 4 が継承する。
