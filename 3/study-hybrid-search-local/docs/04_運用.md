## 1. 初回セットアップ

```bash
# 1. credentials のサンプルから実体を作る
cp env/secret/credential.yaml.example env/secret/credential.yaml

# 2. uv workspace を同期 (host 側で開発する場合)
make sync

# 3. Docker image を build
#    sentence-transformers の model は `hf_cache` volume 経由で初回起動時に download
#    (image には焼き込まない設計、2 回目以降の起動は cache hit で数秒)
make build
```

## 2. PDCA loop (検証実測済)

```bash
make up         # postgres (host port 5433) / meilisearch / redis を up + healthcheck wait
make seed       # 合成 1000 件投入 + Meilisearch index + pgvector embedding + feature_mart
make train      # LightGBM LambdaRank 学習 → ml/registry/artifacts/{run_id}/model.lgb
make evaluate   # NDCG@10 / MAP / Recall@20 を metrics.json に追記
docker compose up -d search-api    # search-api を background で起動
```

## 6. トラブルシューティング

### 6.1 sentence-transformers の初回 download が遅い

Dockerfile では model を image に焼き込まない設計 (image size 削減のため)。
初回起動時に `hf_cache` volume (`docker-compose.yml` で定義) に model (~470MB) が
download される。2 回目以降は cache hit で数秒。

`E5_MODEL_NAME=intfloat/multilingual-e5-base` (768 dim) に変えたい場合は
`definitions/postgres/migrations/0001_init.sql` の `vector(384)` を `vector(768)` に
変更が必要 (volume を作り直す `make clean` も必要)。

### 6.2 pgvector index が無くて遅い

合成 1000 件レベルでは index なしの seq scan で十分速い (~10ms)。
数万件以上にスケールさせる場合は migration に追加:

```sql
CREATE INDEX ON embeddings USING hnsw (embedding vector_cosine_ops);
```

### 6.3 Meilisearch の filter で 400 エラー

`update_filterable_attributes` 完了前に `/search` が呼ばれている可能性。
`make seed` 完了直後に Meilisearch のインデックスタスクが完了するまで数秒待つ。
タスク状態は `curl http://localhost:7700/tasks` で確認。

### 6.4 `model.lgb` が無い (rerank fallback)

`composition_root.py` は `ml/registry/artifacts/latest/model.lgb` を探し、
無ければ `reranker_client=None` で起動。fallback モードでは `final_rank == lexical_rank`。
解消: `make train` を 1 回回す。`/readyz` で `rerank_enabled: true / model_path: ...` が返ることを確認。

### 6.5 ranking_log が空のまま訓練したい

`pipeline/training_job/main.py` は ranking_log が浅い場合 `synthetic_ranking_frames`
で fallback 学習する。`/search` を数回叩いてから再学習で実データ入りに切り替わる。

### 6.6 host port 5432 衝突 (別プロジェクトの postgres)

Phase 3 docker-compose.yml は **`5433:5432`** で host port を 5432 → 5433 にずらしている。
container 間通信は `postgres:5432` (内部) のままなので影響なし。`make api-dev` で host
側 export する際は `localhost:5433` を使う (§3 参照)。

別プロジェクトの postgres も止めたい場合:
```bash
docker stop $(docker ps -q --filter name=postgres) 2>/dev/null
```

### 6.7 Docker container 名衝突

`docker compose up --force-recreate` の途中で古い container が残ると重複名で fail する:
```text
Error response from daemon: Error when allocating new name: Conflict.
The container name "/phase3-search-api" is already in use by container "<hash>"
```

解決:
```bash
docker rm -f phase3-search-api    # 強制削除
docker compose up -d --no-deps search-api
```

### 6.8 postgres volume が古くて DB `hybrid_search` 不在

`docker compose down` (without `--volumes`) → 再起動の場合、旧 volume が再利用され
initdb が走らないため `hybrid_search` DB が不在のまま。symptom:

```text
psycopg.OperationalError: connection failed: ... FATAL: database "hybrid_search" does not exist
```

解決:
```bash
docker compose down --volumes    # volume ごと削除
make up                          # 新 volume + 0001_init.sql 再実行
docker exec phase3-postgres psql -U admin -d hybrid_search -c '\dt'   # 5 テーブル確認
```

### 6.9 `uv sync` で project install 失敗 (build 時)

Dockerfile は `uv sync --no-dev --no-install-project` を使う (project 自体は後で
`COPY app/ ml/ pipeline/` + `PYTHONPATH=/app` で読む)。古い Dockerfile で
`uv sync --no-dev` だけだと `app/ml/pipeline` が COPY されてないタイミングで
hatchling build が fail する。本リポは fix 済 (`infra/run/{services/api,jobs/pipeline}/Dockerfile` 参照)。

### 6.10 container 内で `python -m ...` が依存を見つけない

Dockerfile に `ENV PATH="/app/.venv/bin:${PATH}"` が必要 (uv が作る venv の Python を
default にするため)。古い Dockerfile で system Python が呼ばれると
`ModuleNotFoundError: No module named 'meilisearch'` 等が出る。本リポは fix 済。
