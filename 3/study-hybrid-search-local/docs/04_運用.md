# 04_運用 (Phase 3: 不動産ハイブリッド検索 Local)

Phase 3 のローカル運用手順。Docker Compose 1 stack で完結する。

## 1. 初回セットアップ

```bash
# 1. credentials のサンプルから実体を作る
cp env/secret/credential.yaml.example env/secret/credential.yaml

# 2. uv workspace を同期 (host 側で開発する場合)
make sync

# 3. Docker image を build
#    初回は sentence-transformers の model download (~470MB) が含まれるため数分
make build
```

## 2. PDCA loop

```bash
make up         # postgres / meilisearch / redis を up + healthcheck wait
make seed       # 合成 1000 件投入 + Meilisearch index + pgvector embedding + feature_mart
make train      # LightGBM LambdaRank 学習 → ml/registry/artifacts/{run_id}/model.lgb
make evaluate   # NDCG@10 / MAP / Recall@20 を metrics.json に追記
make serve      # search-api を :8000 で foreground 起動
```

別ターミナルで:

```bash
# /search (3 段検索 = lexical + semantic + RRF + rerank)
curl -s -X POST http://localhost:8000/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"駅近 2LDK","filters":{"max_rent":150000,"layout":"2LDK"},"top_k":10}' | jq

# /feedback (行動ログ)
curl -s -X POST http://localhost:8000/feedback \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"req-0001","property_id":"prop-0001","action":"click"}'
```

`/search` レスポンスの各 item は `lexical_rank` / `semantic_rank` / `final_rank` が
**all non-zero** になっていること (3 系統が動いている証拠)。

## 3. ローカル開発 (Docker なし、host で uvicorn)

```bash
# postgres / meilisearch / redis は make up で立てたまま
export POSTGRES_DSN=postgresql://admin:password@localhost:5432/hybrid_search
export MEILI_BASE_URL=http://localhost:7700
export MEILI_MASTER_KEY=phase3-local-master-key
export REDIS_URL=redis://localhost:6379/0
export E5_MODEL_NAME=intfloat/multilingual-e5-small

make api-dev    # uv run uvicorn --reload
```

## 4. テストと品質ゲート

```bash
make test            # unit test (外部依存なし)
make check           # ruff + ruff format --check + mypy strict + pytest
make check-layers    # AST 境界検査 (google.cloud / kserve / kfp の禁止 import 検出)
make verify-pipeline # integration E2E (Docker Compose 立ち上げ済前提)
```

## 5. 完了判定 (Phase 3 ゴール)

1. `make build` で 3 service `healthy`
2. `make seed && make train` 後 `curl /search` が 3 系統 all non-zero、`final_rank` の rerank score が学習済モデル由来 (fallback 値でない)
3. `make check` exit 0
4. `make check-layers` で `google.cloud` / `kserve` / `kfp` 違反ゼロ
5. `make verify-pipeline` PASS、`ranking_log` row 1+、`/feedback` 200
6. `metrics.json` に `ndcg_at_10` / `map` / `recall_at_20` がすべて `> 0`

## 6. トラブルシューティング

### 6.1 sentence-transformers の初回 download が遅い

Dockerfile build 時に `intfloat/multilingual-e5-small` を image に焼き込むため、
初回 build には数分かかる。既に build 済みなら起動は数秒。
`E5_MODEL_NAME=intfloat/multilingual-e5-base` (768 dim) に変えたい場合は
`definitions/postgres/migrations/0001_init.sql` の `vector(384)` を `vector(768)` に変更が必要。

### 6.2 pgvector index が無くて遅い

合成 1000 件レベルでは index なしの seq scan で十分速い (~10ms)。
数万件以上にスケールさせる場合は migration に追加:

```sql
CREATE INDEX ON embeddings USING hnsw (embedding vector_cosine_ops);
```

### 6.3 Meilisearch の filter で 400 エラー

`update_filterable_attributes` 完了前に `/search` が呼ばれている可能性。
`make seed` 完了直後に Meilisearch のインデックスタスクが完了するまで数秒待つ。
タスク状態は `curl http://localhost:7700/tasks` で確認。

### 6.4 `model.lgb` が無い (rerank fallback)

`composition_root.py` は `ml/registry/artifacts/latest/model.lgb` を探し、
無ければ `reranker_client=None` で起動。fallback モードでは `final_rank == lexical_rank`。
解消: `make train` を 1 回回す。

### 6.5 ポート衝突 (5432 / 7700 / 6379 / 8000)

`docker-compose.yml` の `ports:` を変更するか、衝突する別プロジェクトを `make down` で停止。

### 6.6 ranking_log が空のまま訓練したい

`pipeline/training_job/main.py` は ranking_log が浅い場合 `synthetic_ranking_frames`
で fallback 学習する。`/search` を数回叩いてから再学習で実データ入りに切り替わる。

## 7. クリーンアップ

```bash
make down    # postgres volume を残したまま停止
make clean   # postgres / meilisearch volume + ml/registry/artifacts/* を全削除
```
